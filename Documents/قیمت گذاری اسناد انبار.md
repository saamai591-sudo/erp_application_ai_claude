**Use Case: قیمت‌گذاری اسناد انبار**

**1\. مشخصات**

| **عنوان**    | **مقدار**                                                                                           |
| ------------ | --------------------------------------------------------------------------------------------------- |
| نام Use Case | قیمت‌گذاری اسناد انبار                                                                              |
| Actor        | کاربر مجاز                                                                                          |
| محل          | انبار                                                                                               |
| هدف          | اجرای عملیات قیمت‌گذاری یا برگشت قیمت‌گذاری اسناد انبار برای کالاهای انتخاب‌شده در یک دوره گزارشگری |

**2\. فرم قیمت‌گذاری**

فرم از دو بخش **Header** و **Grid** تشکیل می‌شود.

**2.1 Header**

| **فیلد**      | **نوع**  | **توضیح**                             |
| ------------- | -------- | ------------------------------------- |
| دوره گزارشگری | انتخابگر | دوره‌ای که عملیات روی آن انجام می‌شود |
| نوع عملیات    | انتخابگر | قیمت‌گذاری / برگشت از قیمت‌گذاری      |

**نوع عملیات**

مقادیر:

قیمت‌گذاری

برگشت از قیمت‌گذاری

نوع عملیات تعیین می‌کند که Dialog انتخاب کالا چه کالاهایی را نمایش دهد.

**3\. Grid فرم**

Grid شامل کالاهای انتخاب‌شده است.

| **ستون**              | **توضیح**                                |
| --------------------- | ---------------------------------------- |
| کالا                  | کالای انتخاب‌شده                         |
| گروه حساب             | گروه حساب کالا                           |
| وضعیت                 | وضعیت قیمت‌گذاری                         |
| آخرین دوره قیمت‌گذاری | آخرین دوره‌ای که کالا قیمت‌گذاری شده است |

**انبار در این Grid وجود ندارد.**

قیمت‌گذاری در سطح **کالا** انجام می‌شود و عملیات قیمت‌گذاری کل موجودی کالا در تمام انبارها را دربر می‌گیرد.

گروه حساب صرفاً جهت نمایش و فیلتر کالا استفاده می‌شود و مبنای ثبت وضعیت قیمت‌گذاری نیست.

**4\. انتخاب کالا**

برای اضافه کردن کالا به Grid، کاربر گزینه:

\[ انتخاب کالا \]

را انتخاب می‌کند.

سیستم Dialog انتخاب کالا را نمایش می‌دهد.

**5\. Dialog انتخاب کالا**

Dialog به‌صورت Server Side عمل می‌کند و نباید کل کالاهای سیستم را یکجا به Client ارسال کند.

**امکانات Dialog**

- جستجوی کالا
- فیلتر گروه حساب
- انتخاب چند کالا
- صفحه‌بندی
- نمایش حداکثر 100 ردیف در هر صفحه
- انتخاب کالاها و انتقال آنها به Grid فرم

**6\. فیلتر پیش‌فرض Dialog بر اساس نوع عملیات**

**6.1 نوع عملیات = قیمت‌گذاری**

اگر کاربر در Header گزینه **قیمت‌گذاری** را انتخاب کرده باشد، Dialog فقط کالاهایی را نمایش می‌دهد که:

در دوره گزارشگری انتخاب‌شده هنوز قیمت‌گذاری نشده‌اند.

بنابراین سیستم به‌صورت پیش‌فرض کالاهای قیمت‌گذاری‌شده در آن دوره را از نتایج حذف می‌کند.

مثال:

دوره: فروردین 1405

کالا A → قیمت‌گذاری شده

کالا B → قیمت‌گذاری نشده

کالا C → قیمت‌گذاری نشده

Dialog:

☐ کالا B

☐ کالا C

**6.2 نوع عملیات = برگشت از قیمت‌گذاری**

اگر کاربر گزینه **برگشت از قیمت‌گذاری** را انتخاب کرده باشد، Dialog فقط کالاهایی را نمایش می‌دهد که:

در دوره گزارشگری انتخاب‌شده قبلاً قیمت‌گذاری شده‌اند.

مثال:

دوره: فروردین 1405

کالا A → قیمت‌گذاری شده

کالا B → قیمت‌گذاری نشده

کالا C → قیمت‌گذاری شده

Dialog:

☐ کالا A

☐ کالا C

**7\. جریان اصلی Use Case**

1. کاربر وارد فرم قیمت‌گذاری اسناد انبار می‌شود.
2. سیستم دوره گزارشگری جاری موردنظر فرم را نمایش می‌دهد.
3. کاربر دوره گزارشگری را انتخاب می‌کند.
4. کاربر نوع عملیات را انتخاب می‌کند:
   - قیمت‌گذاری
   - برگشت از قیمت‌گذاری
5. کاربر گزینه **انتخاب کالا** را می‌زند.
6. سیستم Dialog انتخاب کالا را باز می‌کند.
7. سیستم بر اساس نوع عملیات، فیلتر پیش‌فرض مربوطه را اعمال می‌کند.
8. کاربر کالاها را جستجو و انتخاب می‌کند.
9. سیستم کالاهای انتخاب‌شده را به Grid اصلی اضافه می‌کند.
10. کاربر عملیات را اجرا می‌کند.
11. سیستم عملیات را برای کالاهای انتخاب‌شده انجام می‌دهد.

**8\. عملیات قیمت‌گذاری**

در صورتی که نوع عملیات **قیمت‌گذاری** باشد، با اجرای عملیات:

\[ قیمت‌گذاری \]

سیستم برای هر کالای انتخاب‌شده:

1. اطلاعات ورود و خروج کالا را بررسی می‌کند.
2. کاردکس ریالی کالا را محاسبه می‌کند.
3. مبلغ اسناد خروجی را بر اساس روش ارزش‌گذاری میانگین موزون متحرک تعیین می‌کند.
4. اصلاحات مبلغی موردنیاز را محاسبه و ثبت می‌کند.
5. نتیجه قیمت‌گذاری کالا را برای دوره گزارشگری ثبت می‌کند.

قیمت‌گذاری شامل اطلاعات کالا در **تمام انبارها** است و محدود به یک انبار نیست.

**9\. مبلغ اسناد**

مبلغ نهایی هر ردیف سند انبار از رابطه زیر به دست می‌آید:

مبلغ نهایی

\=

مبلغ اولیه

-

مجموع اصلاحیه‌های قیمت‌گذاری

برای یک ردیف سند ممکن است در دوره‌های مختلف چندین اصلاحیه قیمت‌گذاری ایجاد شود.

مثال:

مبلغ اولیه 100

اصلاحیه اول +100

اصلاحیه دوم -20

اصلاحیه سوم +30

\---------------------

مبلغ نهایی 210

اطلاعات هر مرحله قیمت‌گذاری و اصلاحات آن در ساختار مستقل قیمت‌گذاری نگهداری می‌شود.

**10\. قیمت‌گذاری اسناد برگشت**

در صورتی که در فرآیند قیمت‌گذاری به سند برگشت برسیم، ممکن است مبلغ برگشت بر مبلغ اسناد قبلی اثر بگذارد.

در این حالت سیستم باید محاسبه را به‌صورت تکراری انجام دهد.

**الگوریتم**

1. مبلغ برگشت بر اساس کاردکس محاسبه می‌شود.
2. مبلغ محاسبه‌شده برای رسید مرتبط اعمال می‌شود.
3. کاردکس مجدداً محاسبه می‌شود.
4. مبلغ برگشت مجدداً محاسبه می‌شود.
5. مقدار جدید با مبلغ قبلی مقایسه می‌شود.
6. در صورت عدم برابری، فرآیند تکرار می‌شود.
7. زمانی که مبلغ محاسبه‌شده با مبلغ ثبت‌شده برابر شود، فرآیند خاتمه می‌یابد.

**11\. اصلاح اسناد مربوط به دوره‌های قبلی**

اگر سند مربوط به دوره‌ای باشد که امکان تغییر مستقیم مبلغ آن وجود ندارد، سیستم نباید مبلغ اولیه سند را تغییر دهد.

در این حالت یک **اصلاحیه قیمت‌گذاری** برای سند ایجاد می‌شود.

بنابراین:

مبلغ نهایی سند

\=

مبلغ اولیه

-

تمام اصلاحیه‌های صادرشده برای سند

**12\. ثبت وضعیت قیمت‌گذاری**

برای هر کالا و دوره گزارشگری، وضعیت قیمت‌گذاری در جدول مربوطه نگهداری می‌شود.

کلید منطقی وضعیت:

ReportingPeriod + Item

**انبار در این جدول وجود ندارد.**

اطلاعات اصلی وضعیت شامل مواردی مانند:

- کالا
- دوره گزارشگری
- تاریخ/زمان اجرای عملیات

خواهد بود.

**13\. برگشت از قیمت‌گذاری**

اگر نوع عملیات **برگشت از قیمت‌گذاری** باشد، کاربر کالاهای موردنظر را از Dialog انتخاب می‌کند.

سیستم فقط کالاهایی را نمایش می‌دهد که در دوره انتخاب‌شده قبلاً قیمت‌گذاری شده‌اند.

با اجرای:

\[ برگشت از قیمت‌گذاری \]

سیستم مرحله قیمت‌گذاری مربوط به دوره انتخاب‌شده را برای کالاهای انتخاب‌شده برمی‌گرداند. و از جدول وضعیت قیمت گذاری حذف می کند.

**16\. کنترل‌های فرم**

1. دوره گزارشگری الزامی است.
2. نوع عملیات الزامی است.
3. حداقل یک کالا باید انتخاب شده باشد.
4. کالا در Dialog بر اساس نوع عملیات فیلتر می‌شود.
5. در حالت قیمت‌گذاری، کالای قبلاً قیمت‌گذاری‌شده در دوره انتخاب‌شده نباید در نتایج پیش‌فرض Dialog نمایش داده شود.
6. در حالت برگشت، فقط کالاهای قیمت‌گذاری‌شده در دوره انتخاب‌شده در نتایج پیش‌فرض Dialog نمایش داده شوند.
7. انتخاب کالا باید به‌صورت Server Side انجام شود.
8. Dialog در هر صفحه حداکثر 100 ردیف نمایش دهد.
9. قیمت‌گذاری در سطح کالا انجام می‌شود.
10. انبار بخشی از کلید یا وضعیت قیمت‌گذاری نیست.
11. برگشت قیمت‌گذاری در سطح مرحله قیمت‌گذاری انجام می‌شود.

**18\. معیارهای پذیرش**

**AC-01**

کاربر بتواند دوره گزارشگری و نوع عملیات را در Header انتخاب کند.

**AC-02**

با انتخاب «قیمت‌گذاری»، Dialog فقط کالاهای قیمت‌گذاری‌نشده در دوره انتخاب‌شده را به‌صورت پیش‌فرض نمایش دهد.

**AC-03**

با انتخاب «برگشت از قیمت‌گذاری»، Dialog فقط کالاهای قیمت‌گذاری‌شده در دوره انتخاب‌شده را به‌صورت پیش‌فرض نمایش دهد.

**AC-04**

Dialog کالاها را به‌صورت Server Side و حداکثر 100 ردیف در هر صفحه نمایش دهد.

**AC-05**

کاربر بتواند چند کالا را انتخاب و به Grid فرم اضافه کند.

**AC-07**

سیستم وضعیت قیمت‌گذاری را در سطح «دوره گزارشگری + کالا» نگهداری کند.

**AC-08**

قیمت‌گذاری یک کالا شامل اطلاعات آن کالا در تمام انبارها باشد.

**AC-09**

سیستم بتواند برای یک سند در دوره‌های مختلف اصلاحیه‌های قیمت‌گذاری متعدد ایجاد کند.

**AC-10**

مبلغ نهایی سند برابر مبلغ اولیه به‌اضافه مجموع اصلاحیه‌های آن باشد.

**AC-11**

سیستم در مواجهه با برگشت رسید، فرآیند محاسبه تکراری را تا رسیدن به مبلغ پایدار انجام دهد.

**AC-12**

برگشت قیمت‌گذاری یک کالا، مرحله قیمت‌گذاری مربوط به دوره انتخاب‌شده را به‌طور کامل برگرداند و از جدول وضعیت قیمت گذاری ردیفهای مورد نظر را حذف کند.
