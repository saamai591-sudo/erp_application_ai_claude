# ابزار انتقال داده از سیستم‌های قبلی (سام) به ERP

برنامه‌ی کمکی مستقل (Node ≥ 18). داده را از **SQL Server سام** (فقط خواندن) می‌خواند، نگاشت می‌کند و دسته‌دسته به **API ورود داده‌ی ERP**
(`/api/data-migration/*`) می‌فرستد؛ تمام قواعد نوشتن در خود ERP است (`backend/src/services/dataMigrationService.ts`).

## ساختار
- `src/engine.mjs` — موتور (اتصال، اجرای ماژول‌ها، گزارش‌ها). ماژول تازه = یک فایل در `src/modules/` + یک خط در `MODULES`.
- `src/modules/accounting.mjs` — حسابداری (سطح‌ها، انواع سند، دوره‌های مالی، تفصیل‌ها، درخت حساب‌ها، اسناد، گزارش تطبیق).
- `src/samClient.mjs` (فقط SELECT)، `src/erpClient.mjs`، `src/cli.mjs`.
- `test/` — سام جعلی و تست موتور (`node test/run-mock.mjs [--dry-run]`، نیاز به یک ERP آزمایشی).
- گزارش هر اجرا: `reports/<زمان>/` (`errors.csv`، `warnings.csv`، `reconcile.csv`، `summary.json`).

## استفاده
```
npm install
copy migrator.config.example.json migrator.config.json      (سرور سام، آدرس ERP، موبایل کاربر مدیر ERP)
npm run check                          اتصال‌ها و وضعیت (بدون نوشتن)
npm run dry-run                        خواندن از سام و بررسی نگاشت‌ها (بدون نوشتن در ERP)
npm run run                            اجرای واقعی؛ تاریخ قطع سام پرسیده می‌شود (جلالی یا میلادی؛ خالی = همه)
```
رمزها هر بار در ترمینال پرسیده می‌شوند و جایی ذخیره نمی‌شوند. کاربر ERP باید مجوز «تنظیمات › عملیات › مهاجرت داده › اجرای ورود داده» را داشته باشد (مدیر سیستم دارد).

## قواعد مهم
- اجرای مجدد امن است (idempotent): اسناد موجود (دوره + شماره) رد می‌شوند؛ با افزایش تاریخ قطع، فقط اسناد جدید اضافه می‌شود.
- همه‌ی اسناد «تأییدشده» وارد می‌شوند؛ شماره‌ی سند/عطف/روزانه و کد تفصیل‌ها عیناً از سام می‌آید.
- نوع تفصیل‌های بدون موجودیت در ERP (تسهیلات، سایر، قراردادها) به «پروژه» می‌خورند (منشأ در توضیح پروژه).
- ERP هدف باید خالی از اسناد باشد یا فقط داده‌ی همین مهاجرت را داشته باشد؛ طول کد سطح‌های حساب فقط تا وقتی حسابی نیست هم‌سان می‌شود.
- بعد از هر اجرا «گزارش تطبیق» جمع هر دوره و هر حساب را با سام می‌سنجد؛ ناهمخوانی = خطا.
