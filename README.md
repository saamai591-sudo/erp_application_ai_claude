# نرم‌افزار حسابداری (ماژول تنظیمات و اطلاعات پایه)

این نسخه شامل پیاده‌سازی کامل بخش «تنظیمات» و «اطلاعات پایه» طبق مستندات ارائه‌شده است:
نقش کاربری، کاربر، ارز و نرخ ارز، دوره مالی، ساختار سازمانی، مناطق جغرافیایی، نوع تفصیل،
طرف‌حساب (حقیقی/حقوقی)، صندوق، بانک (نوع حساب/شعبه/حساب بانکی)، مرکز هزینه، واحد سازمانی.

ماژول هسته حسابداری (کدینگ حساب‌ها، سند حسابداری، بستن حساب‌ها، گزارش مرور حسابها) در فاز بعدی
روی همین زیرساخت اضافه خواهد شد.

## پشته فنی

- **بک‌اند:** Node.js + Express + TypeScript + Prisma ORM
- **دیتابیس:** PostgreSQL 16
- **فرانت‌اند:** React + TypeScript + Vite
- **احراز هویت:** JWT ساده (شماره همراه + رمز عبور)

## راه‌اندازی سریع با Docker (پیشنهادی)

پیش‌نیاز: نصب بودن Docker و Docker Compose.

```bash
docker compose up --build
```

پس از بالا آمدن سرویس‌ها (چند ثانیه صبر کنید تا PostgreSQL آماده شود)، در یک ترمینال جدید مایگریشن و
داده‌های اولیه را اجرا کنید:

```bash
docker compose exec backend npx prisma migrate dev --name init
docker compose exec backend npm run seed
```

سپس:
- فرانت‌اند: http://localhost:5174
- بک‌اند: http://localhost:4000/api

### کاربر پیش‌فرض برای ورود
- شماره همراه: `0999999999`
- رمز عبور: `Admin@123`

## راه‌اندازی بدون Docker (توسعه محلی)

### ۱. پایگاه داده
یک PostgreSQL محلی یا Docker جداگانه بالا بیاورید و `DATABASE_URL` را در `backend/.env` تنظیم کنید
(نمونه در `backend/.env.example` موجود است).

### ۲. بک‌اند
```bash
cd backend
npm install
cp .env.example .env   # و در صورت نیاز مقادیر را ویرایش کنید
npx prisma migrate dev --name init
npm run seed
npm run dev
```
بک‌اند روی پورت 4000 بالا می‌آید.

### ۳. فرانت‌اند
```bash
cd frontend
npm install
npm run dev
```
فرانت‌اند روی پورت 5173 بالا می‌آید و به‌صورت پیش‌فرض به `http://localhost:4000/api` وصل می‌شود
(قابل تغییر با متغیر محیطی `VITE_API_URL`).

## ساختار پروژه

```
accounting-erp/
├── docker-compose.yml
├── backend/
│   ├── prisma/
│   │   ├── schema.prisma   # شمای کامل دیتابیس
│   │   └── seed.ts         # داده‌های اولیه (نوع تفصیل، ارز پایه، کاربر مدیر)
│   └── src/
│       ├── routes/         # یک فایل به ازای هر فرم/گروه فرم
│       ├── middleware/auth.ts
│       └── utils/coding.ts # منطق کدگذاری خودکار طبق مستند «نوع تفصیل»
└── frontend/
    └── src/
        ├── pages/           # یک صفحه به ازای هر فرم
        ├── components/      # Modal، DataTable، TreeView مشترک
        └── lib/             # اتصال API، احراز هویت، هوک CRUD
```

## نکات مهم پیاده‌سازی

- **کدگذاری خودکار تفصیلی‌ها:** طرف‌حساب، صندوق، حساب بانکی، مرکز هزینه و دوره مالی همگی از
  جدول مرکزی `DetailCodeUsage` برای رعایت قانون «کد نباید در بین همه تفصیلی‌ها، نه فقط همان نوع،
  تکراری باشد» استفاده می‌کنند.
- **کنترل‌های حذف:** فیلد `hasTransactions` روی موجودیت‌های دارای گردش پیش‌بینی شده؛ در فاز بعد
  (با اضافه شدن سند حسابداری) این فیلد به‌صورت خودکار توسط موتور حسابداری به‌روزرسانی خواهد شد.
- **دوره مالی:** پیوستگی دوره‌ها (از‌تاریخ باید بلافاصله بعد از تا‌تاریخ دوره قبل باشد) و محدودیت
  ویرایش فقط برای آخرین دوره، در بک‌اند کنترل می‌شود.
- **طرف‌حساب:** هشدار نام/کد ملی/کد اقتصادی تکراری به‌صورت غیر بازدارنده پیاده شده (کد وضعیت ۴۰۹
  با `warning: true`)؛ فرانت‌اند با دکمه «بله، ادامه بده» درخواست را با `confirmDuplicate: true`
  مجدد ارسال می‌کند.

## گام بعدی پیشنهادی

با تکمیل این زیرساخت، آماده‌ایم که ماژول هسته حسابداری را روی آن بسازیم:
سطح گزارشگری → تعریف حسابها (درختی) → نوع سند → سند حسابداری → تایید اسناد →
افتتاحیه/اختتامیه → بستن حسابها → گزارش مرور حسابها.
